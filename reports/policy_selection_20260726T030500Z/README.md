# Outcome F — Canonical Policy-Selection Evidence Package

**Directory:** `reports/policy_selection_20260726T030500Z/`
**Status:** Canonical frozen Outcome F synthetic benchmark for this branch.
**Supersedes:** `reports/policy_selection_20260726T025426Z/` (earlier `--quick`-scale / Outcome A smoke; keep local, do not treat as canonical).

---

## What this package supports

- On nested synthetic burial-heavy **held-out** regimes, an **oracle** query-specific
  policy selector has higher corrected utility than always-UHT.
- **No** learned / hard / calibrated / selective / soft / staged / contextual gate
  beat always-UHT on that corrected-utility criterion.
- Decision rule Outcome **F** fires: selection is valuable in principle, but current
  gates do not realize it → interim production default **always UHT** (with a
  non-routing safety floor implemented elsewhere in code).

## What this package does **not** support

- It does **not** validate learned routing for production deployment.
- It does **not** replace or overturn the JDIQ manuscript’s repaired-vs-unrepaired
  retrieval null result.
- It does **not** validate the production safety floor on real LLM queries.
- It does **not** use qrels or real provider judgments (synthetic judges only).

## Generation command

From repository root (synthetic judges only; no billed API):

```bash
source .venv/bin/activate
export PYTHONPATH=src
python scripts/run_policy_selection_experiment.py \
  --output-dir reports/policy_selection_20260726T030500Z \
  --overwrite-existing
pytest tests/test_policy_selection.py -q
```

Equivalent non-destructive check (write elsewhere, then diff `gate_rows.json`):

```bash
python scripts/run_policy_selection_experiment.py --output-dir /tmp/ps_verify
```
