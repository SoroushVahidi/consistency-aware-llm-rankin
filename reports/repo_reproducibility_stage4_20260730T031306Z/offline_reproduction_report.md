# Offline Reproduction Report

## What this documents

`scripts/run_offline_validation_workflow.py` (new this stage) is the single
canonical offline reproduction workflow for this repository. It runs
entirely from data already committed to the repository, makes no external
API calls, requires no network access, and never overwrites any committed
canonical output (see `canonical_output_protection_report.md`). This report
records what it actually checks, what was verified by running it, and
which parts of the repository's total evidence base are (and are not)
covered by "offline reproduction" as a concept.

## The workflow's 8 steps (full run, `--only` omitted)

1. **verify-env** — Python version + `verify_canonical_solver_version()`.
2. **input-availability** (x2: ir-audit, real-llm) — confirm every source
   directory each canonical workflow reads from exists.
3. **reproduce-ir-audit** — re-run `scripts/run_ir_evidence_audit.py` into a
   fresh temp directory, byte-compare its 6 deterministic output files
   against the committed `reports/ir_evidence_audit_20260729T182949Z/`.
4. **reproduce-real-llm-reanalysis** — re-run
   `scripts/run_real_llm_clustered_reanalysis.py` into a fresh temp
   directory, byte-compare its 11 deterministic output files against
   `reports/real_llm_clustered_reanalysis_20260730T023745Z/`.
5. **regression-tests** — full `.venv/bin/pytest -q` (skippable via
   `--skip-tests` for fast iteration; a full run takes ~2m50s).
6. **evidence-manifest-validation** — every path referenced by
   `canonical_evidence_inventory.csv` exists (see `validate_canonical_evidence_manifest.py`).
7. **report-link-validation** — every local Markdown link in 5 key
   documents resolves (see `validate_report_links.py`).
8. Final readiness summary (`overall_status`: PASS/FAIL).

`--only {ir-audit,real-llm}` restricts the run to env-check +
input-availability + the one named reproduction step (used by
`make reproduce-ir-audit` / `make reproduce-real-llm-reanalysis`).

`modified_files.csv` for this stage.

## Reproducibility classification

Per this stage's brief, every workflow's reproducibility depends on one of
four categories:

| Category | Workflows |
|---|---|
| **Fully reproducible from a fresh clone + committed data** | `run_ir_evidence_audit.py`, `run_real_llm_clustered_reanalysis.py` (both verified byte-identical this stage); all regression tests in `tests/` |
| **Reproducible only with the repo's own stored (non-regenerated) intermediate data** | The classical backbone tables under `reports/full_calibrated_core/`, `reports/exact_open_source_ilp_repair_investigation/`, etc. — reproducible in the sense that the IR-audit script recomputes derived statistics from these tables, but the tables themselves were generated by underlying pipelines that read `data/raw/` (see below) |
| **Depends on external data / API access, not offline-reproducible** | Original generation of `reports/full_calibrated_core/` and siblings requires HuggingFace dataset downloads (`data/raw/` is mostly gitignored, per `canonical_evidence_inventory.csv`'s CB-01 `reproducibility_status` field); original generation of the three real-LLM studies (`repair_frontier`, `extraction_study`, `repair_diagnostic`) required live provider API calls (OpenAI/Gemini/Cohere), which this repository's re-analysis workflows correctly never repeat |
| **Historical, unsupported for reproduction** | Everything under `reports/_archive/` (Stage 2) — explicitly superseded, not expected to still run against current code |

This workflow validates the first category directly (by actually
re-running it) and the second/third indirectly (by confirming the stored
tables/files it reads from still exist — see `input-availability`), it does
not and cannot validate the second/third categories' original generation
without external data or API access, which is correctly out of scope for
an *offline* workflow.

## Known limitations

- **Figure/PNG outputs are not byte-compared.** `write_publication_figure()`
  in `run_ir_evidence_audit.py` embeds Matplotlib metadata (creation
  timestamp) in its PNG output, so two runs are not guaranteed byte-
  identical even when the underlying data is unchanged; the workflow
  compares the table CSV/MD outputs derived from the same data instead, and
  only confirms the figure file's *existence*, not byte-identity.
- **`reproducibility_manifest.json` is intentionally excluded from the
  comparison set** for the same reason (it embeds `generated_utc` and
  `git.dirty`, which legitimately differ run-to-run).
- **Regression-test step uses the ambient `.venv/bin/pytest` via an
  absolute path**, not a bare `pytest` — this is deliberate, to avoid the
  exact environment-ambiguity mistake this stage's environment audit
  uncovered (see `canonical_environment_specification.md`).
