# Duplicate/Confusing Directory Naming — Investigation and Resolution

Four families investigated this stage, per the brief's criteria (differ only by timestamp/suffix; overlapping outputs; task-number vs. semantic-name conventions; could be mistaken for canonical; share a study name but different schemas).

## 1. `reports/exact_ilp_repair_investigation/` vs. `reports/exact_open_source_ilp_repair_investigation/` — RESOLVED (moved)

- **Canonical**: `reports/exact_open_source_ilp_repair_investigation/` (4.2MB, tracked, used by `scripts/run_ir_evidence_audit.py` and every current test referencing exact-repair evidence).
- **Historical**: `reports/exact_ilp_repair_investigation/` (56KB, was untracked/gitignored).
- **Investigation performed this stage**: read the three files that mention the exact string `exact_ilp_repair_investigation` (`papers/JDIQ_2026/submission/final_anonymous/SOURCE_MANIFEST.md`, `papers/JDIQ_2026/submission/scripts/build_anonymous_supplementary.py`, `papers/JDIQ_2026/submission/scripts/build_final_anonymous.py`). Confirmed: all three use the string only as an internal folder-name **label** inside the anonymous-submission bundle (`supplemental/tables/exact_ilp_repair_investigation/`), and both scripts' own `table_sources`/`table_dirs` dicts map that label to `reports/exact_open_source_ilp_repair_investigation/tables` as the actual read source. There was **no** live reference to the old directory's contents anywhere.
- **Action taken**: moved (plain `mv`, since untracked — no Git history existed to preserve) to `reports/_archive/exact_ilp_repair_investigation_SUPERSEDED/`.
- **Why this was confusing**: near-identical directory names, one clearly a historical predecessor, easy to cite the wrong one from memory or autocomplete. The internal-label coincidence in the submission scripts made it look, at a shallow grep, like an active dependency — it was not.

## 3. `outputs/pub_vote_cmp_all4/` vs. `outputs/pub_vote_cmp_v2/` vs. `outputs/q1_journal_package/` — DOCUMENTED, NOT MOVED

- **Relationship**: `pub_vote_cmp_v2` (two datasets) is the earlier predecessor to `pub_vote_cmp_all4` (four datasets); `q1_journal_package` is derived from `pub_vote_cmp_v2` by `scripts/generate_q1_tables.py`'s own default `--pub-root`.

Moving would break those scripts' documented, still-functional defaults for a reader who explicitly wants to reproduce the earlier multi-scorer result — this is exactly the "a downstream dependency cannot be confidently updated" exclusion criterion (updating 4 scripts' defaults is itself a design decision about whether the historical reproduction path should keep working, not a mechanical path fix).
- **Action taken instead**: added an in-place `HISTORICAL.md` marker file to each of the three directories (see Stage 2's `canonical_location_changes.csv`), stating plainly that it is not the current canonical evidence and pointing to `reports/full_calibrated_core/`.
- **Ambiguous-selection check**: confirmed neither `generate_q1_tables.py` nor `build_paper_evidence_package.py` selects between `pub_vote_cmp_all4`/`v2` via glob/mtime/"latest" logic — both take an explicit `--pub-root`/`--root` CLI argument with a fixed, hardcoded default (`Path("outputs/pub_vote_cmp_all4")` and `outputs/pub_vote_cmp_v2` respectively, in different scripts, both explicit). No hazard found.
