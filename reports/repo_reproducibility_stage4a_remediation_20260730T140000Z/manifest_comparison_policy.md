# Canonical Real-LLM Provenance Manifest: Regeneration and Comparison Policy

## What was wrong

`reports/real_llm_clustered_reanalysis_20260730T023745Z/reproducibility_manifest.json`
was written before `scripts/run_real_llm_clustered_reanalysis.py` was wired up
to the shared `collect_provenance()` implementation in
`src/consistency_ranker/provenance.py` (see
`reports/repo_reproducibility_stage4_20260730T031306Z/provenance_metadata_schema.md`).
The committed file used an ad-hoc, partial schema: it had
`generated_utc`/`generator_script`/`python_version`/`platform`/`random_seed`/
`bootstrap_replicates`/`ci_method`/`paired_test_method`/
`multiple_comparison_correction`/`source_studies`/`population_summary`/the
three `no_new_*` booleans, but was **missing** `schema_version`, `git`
metadata, `dependency_versions`, `solver_version`, `input_file_hashes`,
`output_file_hashes`, and `config` (as a discrete field). This is a full
schema mismatch, not merely a timestamp difference -- it is called out
explicitly here per the Stage 4A brief's instruction not to understate it as
such.

## What was done

The script (`scripts/run_real_llm_clustered_reanalysis.py`) already calls
`collect_provenance()` correctly in `write_reproducibility_manifest()` --
that code was not modified. What was stale was only the **committed output
file**, which predated that wiring. This stage regenerated
`reproducibility_manifest.json` in place by calling
`population.build_population_manifest()` /

## Stable vs. volatile field policy

Because the manifest embeds a wall-clock timestamp, the current git commit
hash, and a dirty-tree flag, two runs of the same analysis will never be
byte-identical even when they are scientifically equivalent. This policy
defines which fields a future automated or manual comparison must require to
match, and which it must ignore.

### Stable fields (must match across reruns for the manifest to be considered equivalent)

- `schema_version`
- `input_file_hashes` (every key and value -- these are hashes of the frozen
  upstream study directories the re-analysis reads, not generated by it)
- `config` (bootstrap replicate count, CI method, paired-test method,
  multiple-comparison-correction method)
- `seeds` (`bootstrap_seed`)
- `independence_cluster_count`
- `output_file_hashes` (every key and value -- these are hashes of this
  run's own result files; a stable rerun must reproduce them exactly since
  the analysis is deterministic given a fixed seed)
- `dependency_versions` (numpy/scipy/pandas/scikit-learn/networkx --
  relevant to numerical reproducibility of the bootstrap/permutation
  machinery)
- `solver_version` (recorded for environment completeness even though this
  workflow does not invoke the exact-repair solver itself)
- `extra.population_summary` and the three `extra.no_new_*` booleans
- `generator_script`

### Volatile fields (may differ across reruns; must be excluded from an equivalence check)

- `generated_utc` (wall-clock generation time)
- `git.commit` (changes as the repository advances; a rerun on a later
  commit with unchanged inputs/outputs is still a valid reproduction)
- `git.dirty` (accurately reflects whatever uncommitted changes happen to
  exist in the working tree at generation time -- this is correct behavior
  per `provenance.py`'s design, not a defect, and must not be required to
  match)
- `python_version` / `platform` (machine-specific; only the numerically
  load-bearing `dependency_versions` and `solver_version` need to match, not
  the full interpreter/OS string)

### Recommended comparison procedure

To compare two `reproducibility_manifest.json` files for scientific
equivalence: parse both as JSON, drop the volatile-field keys listed above
(top-level `generated_utc`, `python_version`, `platform`, and `git.commit`/
`git.dirty` inside the `git` object), then compare the remaining structures
for exact equality. `scripts/run_offline_validation_workflow.py`'s existing
byte-diff check for the other output files in this directory already
implements the equivalent policy implicitly (it diffs everything except this
manifest); this document makes the policy explicit so a future contributor
extending that script to also diff `reproducibility_manifest.json` knows
which keys to exclude rather than requiring full byte equality (which would
never pass) or skipping the file entirely (which would never catch a real
schema/config regression).
