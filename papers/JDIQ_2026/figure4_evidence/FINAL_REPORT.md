## Whether every CI was found

**Yes.** All 24 target cells have a stored `mean_delta_ndcg`, `ci95_low`, and `ci95_high` in the canonical bootstrap table; none were missing or required inference/interpolation.

## Whether any value had to be recomputed

**No statistic was recomputed.** `delta_ndcg`, `bootstrap_ci_low`, and `bootstrap_ci_high` are copied verbatim from `table_bootstrap_delta_ndcg.csv`. `mean_before`/`mean_after` are copied verbatim from `table_graph_ndcg_and_consistency.csv`.

One derived check *was* performed, not a recalculation of the underlying statistic: for every row, `mean_after − mean_before` was asserted to match the canonical `mean_delta_ndcg` to within 1e-6 (see `build_figure4_evidence.py`, the assertion in the join loop). This is a **consistency check between two independently-stored canonical numbers**, not a new bootstrap computation — it passed for all 24 rows with zero failures, confirming the two canonical tables are mutually consistent.

Two derived columns (`significant`, `crosses_zero`, `ci_relation_to_zero`, `effect_direction`) are simple boolean/categorical classifications of the stored CI endpoints (no resampling), documented below and in `build_figure4_evidence.py`.

`bootstrap_std` is **not available** in any canonical source — the pipeline stores only the mean and the 2.5th/97.5th percentile CI bounds, not the full resample distribution or its standard deviation. This column is left blank in `figure4_bootstrap_data.csv` rather than recomputed, since recomputing it would require access to the raw per-resample bootstrap values, which are not stored anywhere in the repository (only the two JSON/CSV summary artifacts exist). If a standard deviation is later required, it would need to be regenerated by rerunning `scripts/run_publication_vote_suite.py` with an instrumented bootstrap routine — out of scope for this evidence-collection task per the "no new experiments" rule.

## A subtlety caught during quality-checking: the zero-boundary convention

A first-pass automated check defined "crosses zero" as the standard inclusive containment test `ci_low <= 0 <= ci_high`. Under that definition, **all 24 rows** — including HotpotQA ms1 Copeland (CI `[0.0, 0.0405]`) — technically "cross zero," because its lower bound is exactly `0.0` rather than negative. That would erase the distinction the manuscript's own planning documents carefully preserve: HotpotQA's interval is qualitatively different from FiQA/SciDocs/BRIGHT's ms1-Copeland intervals, which have **negative** lower bounds (e.g., FiQA `[-0.000515, 0.004236]`) and therefore genuinely straddle zero in both directions.

`FIGURE_SPECIFICATIONS.md` already uses careful language for exactly this reason ("a confidence interval that does not cross zero **below**"). This package's build script (`build_figure4_evidence.py`) now encodes that same three-way distinction explicitly via `ci_relation_to_zero`:

| Category | Definition | Rows |
|---|---|---|
| `exactly_zero` | `ci_low == 0` and `ci_high == 0` | 20 |
| `positive_bounded_at_zero` | `ci_low >= 0` and `ci_high > 0` | 1 (HotpotQA ms1 Copeland) |
| `straddles_zero` | `ci_low < 0 < ci_high` | 3 (SciDocs ms1 Copeland, FiQA ms1 Copeland, BRIGHT ms1 Copeland) |
| `negative_bounded_at_zero` | `ci_high <= 0` and `ci_low < 0` | 0 (none observed) |

`significant = True` only for the `positive_bounded_at_zero` / `negative_bounded_at_zero` categories — i.e., exactly **1 of 24 rows** (HotpotQA ms1 Copeland, mean Δ = +0.0167, 95% CI [0, 0.0405]). This matches the manuscript's existing narrative (`CANONICAL_PAPER_STORY.md`: "A single regime — HotpotQA ms1 — shows positive retrieval repair effect") with no discrepancy. **Recommendation for the manuscript authors:** carry this same careful "does not cross zero below" phrasing into the Figure 4 caption rather than the blunter "CI excludes zero," since the lower bound is exactly zero, not strictly positive.

## Inconsistencies discovered

1. **Figure numbering drift between two planning documents.** `FIGURE_PLAN.md`, `PROJECT_STATUS.md`, `MISSING_COMPONENTS.md`, and `SECTION_EVIDENCE_MAP.csv` (row `F003`) all identify the bootstrap ΔnDCG forest plot as **"Figure 4."** The later, more detailed `FIGURE_SPECIFICATIONS.md` instead numbers this same forest plot **F05**, reassigning **F04** to a different visualization (FAS weight removed vs. retrieval delta scatter). This package follows the majority numbering and the content explicitly requested by the task (ΔnDCG + 95% CI, repair vs. no repair), which matches the forest plot, not the scatter plot. See `FIGURE4_COMPARISON_SELECTION.md` §1 for full detail. **This should be reconciled by manuscript authors before final submission** — it is a numbering/document-sync issue, not a data or evidence problem.
2. **Zero-boundary classification** (see above) — resolved by adding `ci_relation_to_zero`, not a data error, but worth flagging since a naive automated check would have misclassified the one significant row.
3. **No data-integrity problems found.** The two canonical source CSVs are mutually consistent (means minus means reproduce the stored deltas exactly, see above), and the two duplicate copies of the bootstrap table (`final_jis_package`, `jis_final_tables`) are byte-identical to the primary source.
